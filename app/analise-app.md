# Análise de Qualidade — App Delivery (Next.js)

**Data:** 21/07/2026  
**Projeto:** Delivery App (Next.js 15, MUI, React Query, React Hook Form, Zod)

---

## 🔴 Nível 1 — Crítico (bugs ou problemas que quebram funcionalidade)

### 1. `global.d.ts` ainda declara módulos SCSS/SASS
O arquivo declara tipos para `.scss` e `.sass`, mas o SCSS foi removido do projeto. Deve ser limpo ou removido.

### 2. `metadata` genérica no root layout
`title: "Create Next App"` e `description: "Generated by create next app"` — isso vai pro SEO e abas do browser. Deveria ser "Delivery" ou algo relevante ao projeto.

### 3. Middleware não protege a rota `/register`
A rota `/register` não está em `publicRoutes`, então um usuário não autenticado tentando se cadastrar é redirecionado pro login. Precisa adicionar `/register` como rota pública.

### 4. `queryClient` sem configuração de staleTime/retry
O `new QueryClient()` sem opções usa defaults agressivos — refetch em toda mudança de foco, retry 3x. Para uma app delivery isso causa requisições desnecessárias ao backend.

## 🟠 Nível 2 — Qualidade de código (funciona, mas tem problemas técnicos)

### 5. Classe `Api` é uma "God Class"
Uma única classe com métodos de auth, product, category, e delete genérico. Mistura responsabilidades. Ideal seria separar em services por domínio (`authService`, `productService`, `categoryService`).

### 6. Token armazenado via `document.cookie` manualmente
Manipulação manual de cookies no client-side (sem `httpOnly`) é vulnerável a XSS. O token deveria vir como `httpOnly` cookie do backend, ou usar uma lib como `js-cookie` no mínimo.

### 7. `productFormData` no Zod não reflete o uso real
O schema espera `categoryId: number`, mas no `productDialog.tsx` o `product?.categoryId` é tratado como objeto com `.id` e `.name`. Inconsistência entre tipo e uso.

### 8. `forgotPassword.tsx` está em inglês, resto do app em português
"Reset password", "Enter your account's email", "Cancel", "Continue" — deveria estar em pt-BR para manter consistência.

### 9. `productTableItem.tsx` ainda usa `className="box-actions-icons"`
Ficou uma referência a classe CSS que não existe mais (SCSS removido). Deveria ser `sx` como feito nos outros componentes.

## 🟡 Nível 3 — Boas práticas e manutenibilidade

### 10. Imports de fontsource no auth layout
Os imports `@fontsource/roboto` deveriam estar no root layout, não só no auth. MUI usa Roboto por padrão — se não carregar nas rotas privadas, o fallback é sans-serif.

### 11. `headerAdmin` não integra o Drawer
O `HeaderDrawer` está comentado, `handleDrawerToggle` e `handleLogout` são funções vazias. Componente está inacabado.

### 12. `orderItem.tsx` é um componente placeholder
Tem dados hardcoded ("orderDate", "username", "#id") e select sem value controlado. Está incompleto.

### 13. Falta `.env.example`
O código usa `process.env.NEXT_PUBLIC_URL` mas não há documentação de quais variáveis de ambiente são necessárias.

### 14. Falta tratamento de loading/error states genérico
As queries não têm `isLoading` / `isError` sendo renderizados. O usuário vê uma tela vazia enquanto carrega.

### 15. Convenção de nomes inconsistente nos tipos
`authFormData`, `productFormData`, `categoryFormData` — em TypeScript a convenção para types/interfaces é PascalCase: `AuthFormData`, `ProductFormData`, `CategoryFormData`.

## ⚪ Nível 4 — Sugestões de melhoria (nice-to-have)

### 16. `eslint.config.mjs` não customizado
Pode estar com regras default sem customização para React Query, hooks, etc.

### 17. Falta de um tema MUI centralizado
Cores como `#555`, `hsl(220, 30%, 6%)` estão hardcoded repetidamente. Um `ThemeProvider` com palette customizada resolveria.

### 18. Sem loading spinner no submit dos forms
O botão fica disabled mas não mostra indicador visual de progresso.

### 19. Falta `aria-label` nos IconButtons de ação
Botões de Edit/Delete só têm ícone, sem texto acessível para leitores de tela.
